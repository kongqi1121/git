每条建议给出：可行性判定、技术依据、实施要点、**数据泄漏/方法学风险**、预期收益与工作量。

## A. 模型与算法层面

### A1 增加模型对比矩阵（决策树、朴素贝叶斯、SVM）

**判定：✅ 建议做。** 这是最直接回应"KNN 是不是随便选的"的手段，而且实现成本很低。

**技术依据**：

* 现有 `src/model_backends.py` 已经是一个**后端抽象层**（统一
  `fit / predict / predict_proba / kneighbors` 签名），新增三种模型只需在其中扩展
  `kind` 分支，**评估代码零改动**即可复用 LOGO / 分组划分 / 课程外推三套口径 —— 这是本项目
  早先做后端抽象的额外回报；
* 决策树：`DecisionTreeClassifier(max_depth=3~6, random_state=...)`，最大优势是
  **能输出可读的判定规则**（if 缺课 > x 且挂科 ≥ 2 …），对"帮扶建议"很有价值；
* 朴素贝叶斯：特征既有标准化连续量（`age`/`absences`）又有 0/1 指示量，
  应使用 **`GaussianNB`**（对连续特征），并在文档中说明"高斯假设对 0/1 指示变量并不严格成立"；
* SVM：**必须用 `LinearSVC` 或 `SVC(kernel='rbf')` + `probability=True`**。
  注意 `probability=True` 会在内部做 Platt 校准、显著变慢；若只要 F1/recall 可先不开概率，
  只在需要概率时再开。

**实施要点**：

* 三者都要跑**同一套三套口径**（LOGO / 10 次分组划分 / 课程外推），否则不可比；
* 计算量评估：`SVC(kernel='rbf')` 在 LOGO 下要训练 668 次，是本次新增中**最慢**的一项
  （KNN 免训练、逻辑回归收敛极快），建议对 SVM 只跑"10 次分组划分 + 课程外推"，
  并在报告中注明"SVM 未跑 LOGO 的原因是全折重训成本过高"，而不是悄悄省略。

**数据泄漏风险**：低。但要守住两条：
① 标准化器必须每折重新 `fit`（现有 `_fit_pipeline` 已保证）；
② **不要用测试集挑"表现最好的模型"** —— 应报告完整对比矩阵，并说明主模型的选择依据是
"预警场景下 recall 优先"，而不是"KNN 分数最高"。

**预期收益**：中。能证明选择有依据，但**存在一个必须接受的现实：新模型有可能在某个指标上超过 KNN**。
这正是要如实报告的：若决策树 recall 更高，就应把"主模型是否更换"作为一个**真实结论**写进报告，
而不是维护原选择。

**额外收益（容易被忽略）**：决策树规则可以与"帮扶建议模板"打通，
让建议从"特征贡献差距"升级为"可读的判定路径"。

### A2 加入概率校准（`CalibratedClassifierCV`）

**判定：⚠️ 需改造后做。** 方向完全正确 —— 它精确命中本项目的已知短板
（k=1 时 `predict_proba` 只能取 0/1，三档等级**实际退化为两档**）。但有一个**必须处理的方法学约束**。

**必须避开的坑**：`CalibratedClassifierCV` 自身会做内部交叉验证来拟合校准曲线。
如果直接在**全量数据**上包装再评估，那么校准器"见过"测试折的数据 ——
概率会变得很好看，但**评测结果偏乐观**。正确做法是：
**把校准塞进现有 CV 的训练折内层**（即 `_fit_pipeline` 内部创建
`CalibratedClassifierCV(KNN, cv=3, method='sigmoid')` 并只用训练折 fit）。

**技术要点**：

* 方法选择：`method='sigmoid'`（Platt）比 `'isotonic'` 更稳。原因：k=1 的基础模型输出
  **只有两个取值（0/1）**，isotonic 在这种极低分辨率的输入上容易过拟合出阶梯函数；
  Platt 假设一个参数化的 S 形映射，更稳健；
* **关键认知（报告里必须写清）**：概率校准**不会改善排序能力**，
  因此 **ROC-AUC / F1 / recall（在阈值 0.5 下）不会有本质提升**；
  它改善的是**概率的数值意义**，从而让 0.3 / 0.7 的等级阈值**第一次真正可用**；
* 评价指标要换：校准优劣的正确指标是 **Brier 分数**与**可靠性曲线（reliability diagram）**，
  而不是 accuracy/F1。建议同时报告"校准前 / 校准后"的 Brier 分数与分档人数分布
  （现状是分档只剩两档，校准后应恢复为三档）；
* 计算量：校准内部 CV=3，等于把 668 折的 KNN 训练量 ×3~4。KNN 在 1044 条上很便宜，
  属于可接受范围（预计从当前 9 秒量级升到分钟量级）。

**预期收益**：高（且是"修掉一个已知缺陷"级别的收益）。
校准后应能给出诚实的三档名单，这正是辅导员实际需要的东西。

### A3 特征选择（RFE 或基于置换重要性的筛选）

**判定：⚠️ 谨慎做。** 方法没错，但**收益不确定、风险不低**，是本清单里我最不推荐优先做的一项。

**风险一：必须嵌进 CV，否则是泄漏**
RFE 用标签选特征。若在全量数据上选出子集再做 LOGO，等于**用全部数据的标签参与了特征决策**，
指标会偏乐观（这是特征选择最经典的泄漏形式，比标准化泄漏更隐蔽）。
正确做法是在每个训练折内部做 RFE，代价是再次 ×668 次重训。

**风险二：本项目信号本来就稀疏，筛选可能筛不出东西**
已实测的两条硬证据：
* 单特征最优准确率只有 **0.8017**（基线 0.7797）→ 没有强单变量信号；
* 置换重要性中最大值（作业提交率 0.0727）与最小值仅差约 2 倍 → **没有单特征独揽贡献**。

在这种"信号分散、每个特征都很弱"的情形下，删除 20~30 个弱特征很可能**不提升甚至略降**。
这本身不是不能做 —— **但报告方式必须诚实**：要么有提升就写提升，要么没有提升就明确写
"特征选择在本数据上未带来提升"，**绝不允许反复调整筛选阈值直到某次结果变好再报告**。

**风险三：置换重要性的已知局限**
三科/多列高度相关的特征会**分摊重要性**（本项目 UCI 特征的指示列之间也彼此排斥相关）。
按重要性阈值粗暴剔除，可能把"单独看很弱、但联合起来有用"的特征删掉。
建议若要做，用**基于置换重要性 + 分组剔除、逐轮评估**，而不是一次性 RFE 到固定特征数。

**建议的实施顺序**：先做 C3（置信区间）再考虑 A3 ——
否则无法判断"提升 0.01"是真提升还是划分噪声（本项目 F1 的标准差就有 0.04 量级）。

**预期收益**：低~中。**主要价值在"可解释性"而非性能**：若能把 39 个特征压到 8~10 个
且性能基本不降，对报告和答辩的说服力提升明显。

### A4 逻辑回归 `class_weight='balanced'` 对 recall 的影响

**判定：✅ 性价比最高的一项。** 一行参数，直接对症。

**技术依据**：
* 当前对照模型逻辑回归的 recall 只有 **0.2391**（精确率 0.5500）——
  这是典型的"模型偏向多数类"的表现（正类仅 22%），`class_weight='balanced'`
  会按类别频率倒数加权损失，**正是为这种情形设计的**；
* 现有配置里 `class_weight=None` 是**刻意设置**以保证与手写版口径一致；
  现在要做的正是把它作为**一个专门的对照实验**（而不是直接改默认值）。

**实施要点**：
* 做成**两个版本对照**：`None` vs `'balanced'`，而不是替换；
* 报告时**必须 precision / recall / F1 三个一起给**。加权一定会拉高 recall，
  但会牺牲 precision（很可能从 0.55 掉到 0.4 以下）——
  只看 recall 上升就宣称"改进"是不诚实的；
* 同时给出**代价敏感视角**（与 C2 配套）：`balanced` 等价于把假阴性代价提高若干倍，
  正好可以用 C2 的代价曲线说明"在什么人力条件下该用它"；
* 顺带值得一试的同类项：`SVC(class_weight='balanced')`、`DecisionTreeClassifier(class_weight='balanced')`
  （若做了 A1）。

**预期收益**：中~高。这是本次所有算法改动里**最可能真正提升 recall 的一项**，
而且成本几乎为零。若 `balanced` 版 recall 显著高于 KNN(k=1) 的 0.3435，
那么"主模型选择"就需要重新讨论 —— 请把这种可能性提前接受。

### A5 特征相关性热力图

**判定：✅ 建议做。** 纯可视化，成本低，且能揭示一个真实问题。

**技术依据与实施要点**：
* 39 个特征里有大量**同类别的互斥指示列**（如 `Mjob_teacher`、`Mjob_health`、`Mjob_at_home`…），
  它们在构造上天然负相关，热力图会直接显示成块状结构 —— 这**恰好能可视化说明
  "固定 schema 编码"的代价**，是有价值的讨论点；
* 相关性用什么系数：`age`、`Medu`、`studytime` 是**有序等级量表**而非等距连续量，
  严格说 **Spearman 比 Pearson 更合适**。建议两张都给（或至少在图注中说明用了哪一种）；
* 与置换重要性**并排展示**能形成一个完整的论述：热力图说明"哪些特征信息冗余"，
  重要性说明"哪些特征对预测有用"。

**需要注意的表述纪律**：
* 相关系数高 **不等于** 多重共线性会导致模型失效（KNN 对共线并不敏感，
  逻辑回归加 L2 也基本吃得住）；
* 本项目**不做因果解释**：`Dalc`/`Walc`（饮酒）与成绩的相关**不能**解读为"饮酒导致成绩差"。
  热力图的图注里应写明这一点（现有 README 已声明，图表也要跟上）。

### B2 增加"模型选择理由"章节

**判定：✅ 可做，但必须诚实 —— 理由不是无条件的。**

这是本清单里**最容易写成"自圆其说"的一节**，需要特别注意。可站得住的技术理由有三条：

1. **评估指标与业务目标对齐**：预警场景的核心风险是**漏报**（把真需要关注的学生判成正常），
   因此 **recall 优先于 precision**。实测 KNN(k=1) recall **0.3435** > 逻辑回归 **0.2391**，
   所以选 KNN；
2. **非参数假设更弱**：逻辑回归隐含"决策边界线性"的假设。本项目的消融实验显示
   加入早期成绩后准确率能到 0.9167，而无早期成绩时最优单特征只有 0.8017 ——
   说明可用信号很弱且关系不线性，非参数模型更合适；
3. **概率输出的可解释路径**：KNN 的 `predict_proba` 有明确的机制解释
   （"最近 k 个同学里有几个是高风险"），对辅导员比线性得分更直观。
   这条在 k=1 时要如实补一句：**k=1 时概率退化，这正是 A2 要解决的问题**。

**必须同时写进这一节的反面**：
* 逻辑回归在 accuracy（0.7893 vs 0.7347）与 precision（0.5500 vs 0.3854）上**都优于 KNN**；
* 两者 F1 差距（0.3632 vs 0.3333）**小于 10 次划分的标准差（0.0404）**，
  所以严格说"KNN 更好"只在 recall 口径下成立；
* 因此诚实的表述是：**"在 recall 优先的预警口径下选 KNN；若辅导员人力紧张、更怕误报，
  逻辑回归更合适"** —— 而不是"KNN 全面更优"。

### B3 补充"失败实验"记录

**判定：✅ 强烈建议。** 这是本项目**已经具备素材、只需整理**的一项，
而且是提升可信度最有效的手段。

**已有素材（全部为真实发生的失败，可直接成文）**：

| 失败项 | 现象 | 结论/处置 |
|---|---|---|
| 硬阈值打标 | 单次划分指标**全 1.0000** | 改为概率化打标 + 交叉样本设计 |
| 向量化距离判自匹配（`== 0`） | 灾难性抵消，自身距离实测 **1.69e-07**，完全判不出自匹配 | 改用按索引精确排除 |
| 阈值判自匹配（`< 1e-9`） | 误删"特征完全相同的不同学生"，邻居数不足（20 条里 6 条出错） | 同上 |
| 浮点复核判据 | 要求"严格相等"→ 误判失败（实际差异 3.55e-15，浮点加法不满足结合律） | 改为相对误差容差 |
| 并列判据（两版都错） | ① 要求全部点概率一致 → 误报；② 查"第 k 与 k+1 是否相等" → 漏判 | 改为逐行判定并列 |
| 学生身份匹配用全部特征 | 只识别出 39 组"疑似重叠"（实际 **372 名**） | 改用 15 个跨课程稳定字段 |
| 三档等级浮点切点 | "中"档被完全跳过，只剩**高 637 / 低 407** | 改为枚举整数切点 |
| `n_jobs=-1` | joblib 线程池命名管道被拒 → `PermissionError [WinError 5]` | 固定 `n_jobs=1` |
| 指标文件共用 | `--auto --legacy` 覆盖 v2 真实指标（`KeyError: logo_knn`） | v1/v2 汇总分文件 |
| 模拟数据污染主数据集 | 400×13 模拟数据写进了 UCI 数据集文件 | 路径分离 + 内容体检 + 自动重建 |

**建议补充写法**：每条写"现象 → 根因 → 处置 → 如何验证已修好"。
这比只列成功结果更有说服力，也是答辩时最能体现工程能力的部分。

### B4 增加"业务落地建议"

**判定：✅ 强烈建议。** 目前项目的短板恰恰是"指标有了，但没人说清它意味着什么"。

**应给出的具体内容（用已实测的数字换算）**：

* **工作量换算**：LOGO 主口径下 TN=688 / FP=126 / FN=151 / TP=79。
  按 1044 条记录算，系统会把 **205 人**（TP+FP）放进"需关注"名单，
  其中只有 **79 人**（38.5%）是真的不及格 —— 也就是**辅导员每约谈 5 人，约 3 人属于误报**；
* **漏报风险**：151 名真实高风险学生没有被系统抓到（漏报率 65.7%），
  **因此系统绝不能替代人工排查**，只能作为"优先关注顺序"的排序工具；
* **与人工复核的配合方式**（核心建议）：
  * 用**概率排序**而不是二值判断来分配人力：先看概率最高的前 N 名（N 由人力决定）；
  * 对"高风险"档（概率 > 0.7）做**必然复核**；对"中"档做**抽样复核**并回填真实结论；
  * 明确**人机分歧的处理规则**：当人工判断与模型相反时，**以人工结论为准**，
    并把该样本作为下一轮的校准依据（这正好与 A2 的概率校准形成闭环）；
* **降漏报的代价**：若要提高 recall，必须下调判定阈值。可引用本项目已有的实测曲线
  （阈值 0.10 时 recall 0.9832、precision 0.5442；阈值 0.90 时 precision 1.0000、recall 0.1092），
  把"多抓一个人"与"多误报几个人"的兑换率摆给辅导员看（与 C2 天然配套）；
* **明确不可用途**：所有输出**不得**用于学籍、评奖、评优、处分 —— 本项目数据为公开学术数据集，
  与任何真实在校学生无关。

**预期收益**：高。这一节能把项目从"跑通了一个模型"提升为"给出了一个可用的工作流程"。

## C. 实验层面

### C1 时间维度验证（按学期/学年划分）

**判定：⚠️ 只能做近似，严格的"时间外推"在本数据上无法实现。** 这是本清单里唯一一条
**数据条件不支持**的建议，需要如实说明而不是硬做。

**为什么做不到**：
* UCI *Student Performance* 数据集**没有任何时间戳或学期/学年字段**，
  它是两所学校在**同一次问卷/成绩采集**中得到的横截面数据；
* 因此**不存在**"按时间切分训练集/测试集"的可能。若强行按行号或随机切分并称之为
"时间外推"，那是**错误标注实验口径**——比不做更糟。

**可以做的三个近似替代（按推荐度排序）**：

1. ✅ **课程外推（已实现）**：用数学课训练、葡语课测试（反之亦然）。
   虽然这不是时间维度，但**是真实的分布外检验**，已实测 KNN 数学→葡语 acc 0.6610、
   葡语→数学 acc 0.7038，性能确实进一步下降 —— 这是本项目最接近"外部有效性"的证据；
2. ✅ **提前预警口径（真正的业务时间顺序）**：主口径已经**剔除 G1/G2**，只用行为/背景特征，
   这在业务语义上就是"**期中之前**做预测"。可以把这一点**明确写成"时间语义上的提前预测"**
   （不需要改动数据，只需把口径讲清楚）：预测时点 = 第 1 学期成绩出来之前，目标是第 3 学期成绩；
3. ⚠️ **按 G2 分层做"伪时间"划分**：以第二学期成绩的分布位置构造两个"批次"
   （例如 G2 较低/较高两半），一半当"历史"、一半当"新批次"。必须明确标注这是
   **人为构造的分布偏移**、**不是真实时间切分**，仅用于检验"分布漂移下的鲁棒性"。
   诚实提示：这种做法会引入"以 G2 分层"的选择效应，结论只能谨慎使用。

**结论**：建议**不做** 3，把 1 与 2 写清即可；若一定要做，必须在文档里显著标注其构造性质。

### C2 代价敏感评估（误报/漏报不同代价 + 代价曲线）

**判定：✅ 建议做，且与 B4 是同一件事的两个面。** 但有一个**必须守住的纪律**。

**技术依据**：
* 现有 `evaluate.threshold_sweep()` 已经算出了阈值 0.10~0.90 的
  precision / recall / F1 / 预测正类数，**代价曲线的原料已经齐了**，只需换算；
* 代价函数定义（标准做法）：
  `总代价 = C_FN × FN + C_FP × FP`，其中 FN=漏报（151）、FP=误报（126）。
  更实用的是给出**人均代价**与"**每千人总代价 vs 阈值**"曲线；
* 建议同时画**代价比率敏感性**：令 `C_FN = 1`，`C_FP ∈ {0.1, 0.2, 0.5, 1}`，
  观察最优阈值如何移动。这能直接回答"什么人力条件下该把阈值调到多少"。

**纪律要求（重要）**：
* **代价比必须作为"假设"给出，不能从数据里推**。真实的"漏报一个学生的代价"是
  教育决策问题（涉及辅导员时间、学生发展后果），数据集里没有，也不能编造；
  建议用"辅导员约谈 1 人 ≈ 0.5 小时，漏报 1 人 ≈ 需要额外补救 2 小时"这类
  **显式声明的场景假设**，并说明这是场景设定而非测量值；
* **阈值绝不能在测试集上选**。本项目已有正确做法
  （`_tune_threshold_within_training`：在训练集内部用 3 折分组 CV 选阈值），
  代价曲线也应遵循同样口径：**曲线可以画在测试集上用于展示，但"选出来的工作点"
  必须来自训练侧**，否则就是把测试集当验证集用；
* 展示时给两条曲线更清楚：**默认阈值 0.5 的固定工作点** vs **按给定代价比选出的工作点**。

**预期收益**：中~高。它是把"要不要用这个系统"讲清楚的关键工具。

### C3 增加 95% 置信区间

**判定：✅ 必做。** 成本极低（现有产物已具备全部原料），收益是统计严谨性。

**技术依据与实施要点**：
* 现有 `results/metrics/split_details.csv` 已存有 10 次划分**每一次的**指标与混淆矩阵
  → **不需要重跑**，可直接离线算区间。建议同时给两种区间，并说明差别：
  * **t 区间**：`mean ± t(0.975, 9) × s/√10`（df=9，t≈2.262）——
    假设指标近似正态，样本量只有 10，t 分布比正态更合适；
  * **Bootstrap 百分位区间**：对混淆矩阵做**分层重抽样**（保持正负类比例），
    重抽 2000 次，取 2.5% / 97.5% 分位。对 F1 这类非线性指标更稳健；
* 关键提醒（要在报告里写）：**LOGO 的 668 折预测彼此高度不独立**
  （同一名学生只被留出一次，但特征空间中相邻样本互相影响），
  因此 **LOGO 的"标准误"不能按独立同分布直接算**；
  本项目 LOGO 是**确定性**结果（无随机划分），严格说它没有抽样置信区间，
  其不确定性来自"这一批数据"而非"这一次划分"。
  → 正确做法是：**对 10 次划分报 t 区间 / bootstrap 区间**，
  对 LOGO **只报点估计**并注明其确定性；
  若一定要给 LOGO 区间，只能对**样本本身**做 bootstrap（即重抽学生），
  此时必须**按学生整组重抽**（因为存在 372 名同修两门课的学生），这一点极易写错。

**预期收益**：高（严谨性），成本极低。**建议在 A3（特征选择）之前完成** ——
否则无法判断任何"性能提升"是否超出噪声。

### D3 配置 GitHub Actions CI

**判定：✅ 建议做。** 项目已托管 GitHub，收益明确（防止改动破坏主流程）。

**可落地的两种工作流（建议都配）**：

1. **每次 push / PR 触发（快，2 分钟内）**
   `pytest` 单元测试 + `python -m py_compile` 全量编译检查 + `python main.py --step data` 的
   数据构建（用缓存）。**不要**在每次 push 跑完整 `--auto`，太慢且没必要；
2. **定时（每日一次）或手动触发（慢）**
   `python main.py --auto` 全流程，用于验证主流程未被破坏，并归档指标快照。

**必须注意的环境约束（本项目实测过的坑）**：
* **`n_jobs` 必须为 1**：GitHub Actions 的容器环境通常不会触发本机的命名管道限制，
  但保持 `n_jobs=1` 可保证 CI 与本地结果**数值逐位一致**，这点比"跑得快点"更重要；
* **数据下载**：CI 需要联网拉 UCI CSV。建议① 在 workflow 里加 `actions/cache`
  缓存 `data/uci_raw/`；② 增加一个**断网可跑的测试子集**（用 fixture），
  保证网络故障时 CI 不至于全红；
* **不要提交生成物**：现有 `.gitignore` 已排除原始数据与数据集，
  CI 里应重新生成（`--step data`）而不是依赖仓库里的文件；
* **随机性**：所有实验代码已固定种子，因此同一提交的 CI 结果应可复现；
  但 `appendix` 报告里的 `speedup_x`、`elapsed_sec`、`timestamp` 属环境相关字段，
  **CI 不应把这些字段当作断言对象**（否则会随机失败）。

**预期收益**：中。对单人实训项目属于"锦上添花"，但对"改完不确认就提交"的风险控制有效。

### A.2 C3 实测：置信区间与配对比较（**修正了原来的说法**）

10 次分组划分的 t 区间（df=9，t=2.262）：

| 模型 | 指标 | 均值 | 95% 置信区间 |
|---|---|---|---|
| KNN(k=1) | F1 | 0.3984 | [0.3696, 0.4273] |
| KNN(k=1) | recall | 0.3731 | [0.3337, 0.4125] |
| 逻辑回归 | F1 | 0.3636 | [0.3327, 0.3944] |

**配对比较（KNN − 逻辑回归）**：accuracy **−0.0463**、precision **−0.1612**、
recall **+0.1087**、F1 **+0.0348**，四项 p 均 < 0.05。

**修正**：原先我写"两者 F1 差距小于标准差，所以差不多"——**这个说法不准确**。
正确做法是把同一批划分配对相减（两模型跑的是完全相同的 10 次划分），
配对检验表明 F1 差异是**可重复的**（同向、区间不含 0）。
同时它也确认 KNN 的优势**不全面**：accuracy 与 precision 上逻辑回归显著更高。

**按学生整组重抽的 bootstrap**（2000 次有效重抽）：LOGO F1 区间
[0.3015, 0.4234]；而"按记录重抽"给出 [0.3081, 0.4167] —— **确实更窄**，
印证了 372 名同修两门课学生的重复计数陷阱真实存在。

|---|---|---|---|---|---|---|
| KNN(k=1) | 0.7347 | 0.3854 | 0.3435 | 0.3632 | **151** | 126 |
| 逻辑回归（默认） | 0.7893 | 0.5500 | 0.2391 | 0.3333 | 175 | 45 |
| **逻辑回归(balanced)** | 0.7184 | 0.4070 | **0.6087** | **0.4878** | **90** | 204 |

**A1（模型对比矩阵）实测**（7 个模型，同一口径，Δ = 该模型 − KNN）：

| 模型 | accuracy | precision | recall | F1 | ΔF1 | Δrecall |
|---|---|---|---|---|---|---|
| **逻辑回归(balanced)** | 0.7182 | 0.4242 | **0.6158** | **0.5015** | **+0.1030** | **+0.2427** |
| 高斯朴素贝叶斯 | 0.7582 | 0.4776 | 0.4945 | 0.4850 | +0.0865 | +0.1214 |
| KNN(k=1)（主模型） | 0.7422 | 0.4312 | 0.3731 | 0.3984 | — | — |
| 决策树(depth=4) | **0.7912** | 0.5955 | 0.2949 | 0.3907 | −0.0078 (p=0.75) | −0.0782 |
| 逻辑回归（默认） | 0.7885 | 0.5924 | 0.2644 | 0.3636 | −0.0348 | −0.1087 |
| 线性 SVM | 0.7783 | 0.5314 | 0.0620 | 0.1066 | −0.2918 | −0.3111 |
| 多数类基线 | 0.7797 | 0 | 0 | 0 | — | — |

**结论（必须如实写入报告）**：

1. **`class_weight='balanced'` 的逻辑回归在 recall 与 F1 上显著优于当前主模型 KNN(k=1)**，
   两套口径（10 次分组划分 + LOGO）一致：
   * LOGO：recall **0.6087 vs 0.3435**、F1 **0.4878 vs 0.3632**；
   * **多抓出 61 名真实高风险学生**（漏报 151 → 90），代价是多 78 个误报；
   * 配对检验 Δrecall=+0.2427、ΔF1=+0.1030，p < 0.001。
2. **高斯朴素贝叶斯同样在 recall/F1 上显著优于 KNN**（Δrecall=+0.1214）。
3. **线性 SVM 表现很差**（recall 0.0620），说明该数据上线性硬边界不合适 ——
   这也侧面支持"非参数/加权类方法更合适"的判断。
4. **决策树 accuracy 最高**（0.7912，高于基线与所有其他模型）且 F1 与 KNN 基本持平
   （差异不显著，p=0.75），同时**可导出可读规则**，对生成帮扶建议很有价值。
5. 因此原先"选 KNN 是因为 recall 优先"的论证**在当前证据下不成立**：
   有一个模型在 recall 优先的同一口径下明显更好。

**建议的处理方式（诚实且不违反项目要求的做法）**：
* **保留 KNN 作为实训规定的主模型与对照基线**（项目要求），但在报告与 README 中
  **明确写出"存在更优模型"的实测证据**，并把 `balanced` 逻辑回归列为
  **推荐的实际生产方案**；
* 不要悄悄更换主模型而不说明，也不要因为"选了 KNN"就隐去这条不利证据；
* README 的「为什么选 KNN」一节已相应改写为"在项目约束下选 KNN + 说明何种条件下应换模型"。

### A.4 A2 实测：概率校准（k=1 概率退化的正解）

（详见 `results/metrics/calibration.json` 与图 18）

* 校准**不改善排序能力**：F1 / recall 在固定阈值下基本不变；
* 它改善的是概率的**数值意义**：Brier 分数与 ECE 下降，
  概率取值从 **2 个（k=1 时只有 0/1）扩展到连续值**；
* 由此**三档风险等级（低 < 0.3 / 中 0.3~0.7 / 高 > 0.7）才真正可用** ——
  这是 k=1 概率退化的对症解法。

### A.5 C2 实测：k=1 使代价敏感分析退化（另一个决定性限制）

代价敏感分析（阈值只在训练侧选）的结果暴露了一个此前未意识到的问题：

| C_FP/C_FN | 选定阈值 | precision | recall | 名单人数 |
|---|---|---|---|---|
| 0.05 | 0.05 | 0.4312 | 0.3731 | 62.5 |
| 0.20 | 0.05 | 0.4312 | 0.3731 | 62.5 |
| 1.00 | 0.05 | 0.4312 | 0.3731 | 62.5 |
| 2.00 | 0.05 | 0.4312 | 0.3731 | 62.5 |

**所有代价比选出完全相同的阈值与名单** —— 原因是 k=1 时概率只有 0 和 1，
任意阈值落在 (0, 1) 之间都产生完全相同的结果，**阈值扫描退化为一个点**。

**这意味着**：用 KNN(k=1) 时，"按辅导员人力调整工作点"这一使用方式
**在数学上无法实现**。而连续概率的模型（如 balanced 逻辑回归）可以。
这是选择模型时的一个**功能性约束**，比单纯的指标高低更关键。

### A.8 A3（特征选择）为何放在最后且尚未实施

评审阶段即判定其为"收益不确定、风险较高"的一项，理由是：

* 本项目**信号本就稀疏**：最优单特征准确率仅 0.8017，仅比基线 0.7797 高 2.2 个百分点；
* 置换重要性的最大值与最小值仅差约 2 倍，**没有单特征独揽贡献** →
  在这种情形下删除弱特征很可能**不提升甚至略降**；
* 且 RFE 必须嵌进 CV 内层，否则构成泄漏；实施成本高。

**后续若要实施，验收标准建议为**：在 LOGO 与 10 次分组划分两套口径上**同时**不劣于现状，
且特征数显著下降（例如 39 → 10 以内）；**若没有提升，必须如实写成"未带来提升"**，
不得反复调整筛选阈值直到某次结果好看。
