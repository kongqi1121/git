# 八天开发小结（dev_log_8days.md）

**项目**：基于机器学习的校园学生成绩风险预警与学业帮扶系统
**说明**：本文把整个项目按 8 个工作日的开发节奏切成 8 份，
每天记录 **当日目标 → 主要工作 → 遇到的问题 → 当日真实产出（指标/结论）→ 涉及文件**。

**写作原则（与 README、experiments.md 一致）**：

1. 每天的指标数字都来自当日代码的**真实运行结果**，没有编造或事后美化；
2. **遇到的失败与 bug 一并记录** —— 本项目最有价值的部分恰恰是这些被挖出来的真实问题；
3. 每条结论都标注可复现命令或产物路径。

> **合规声明**：主数据为 UCI 公开学术数据集（已匿名化，CC BY 4.0）；
> 对照数据为本项目生成的模拟数据。所有输出仅用于教学实验，
> **不得用于任何真实学籍、评奖、评优或处分决策**。

## 第 1 天：项目框架搭建与模拟数据生成

### 当日目标

搭起可运行的工程骨架，并解决题目提出的**最大风险**：
自建数据偏"干净"会导致指标虚高（题目提示"第 4 天已实测到单次划分全部满分"）。

### 主要工作

1. 建立目录结构 `data/ src/ results/{figures,metrics,models}`、`main.py`、三份文档骨架；
2. 编写 `src/config.py`，把路径、特征列、k 候选、风险等级阈值、随机种子**集中定义一处**
   （避免各模块口径漂移）；
3. 编写 `src/generate_data.py`：从原有 5 人 `scores.csv` 扩写为 400 条模拟数据；
4. 设计**四道防线**防止数据过于干净：
   * 潜在能力因子（3 档混合分布）+ 行为因子 + 噪声建模，制造"能力强但态度差"的交叉样本；
   * **概率化打标**：加权风险评分 → 分位数红线 → `sigmoid` → **随机抽样**定标签（不是硬阈值）；
   * 双标签口径：`risk_level`（三档）与 `risk_label`（二分类）用不同分位数标准；
   * 自动"干净度"体检：扫描"单特征 + 最优阈值"能达到的最高准确率。

### 遇到的问题

* 最初的硬阈值打标版本，单次随机划分出现**全部指标 1.0000**，数据没有任何区分难度；
  → 改为概率化打标 + 交叉样本设计后解决。
* 环境实测**没有 scikit-learn**（`ModuleNotFoundError: No module named 'sklearn'`），
  因此当天确定的路线是：主模型用 numpy 手写 KNN，对照模型用 numpy 手写逻辑回归。

### 当日真实产出

| 检查项 | 实测值 | 判定 |
|---|---|---|
| 样本数 | 400 | ✅ 落在 300~500 |
| 高风险比例 | **0.2975**（119/281） | ✅ 落在 20%~35% |
| 三档等级分布 | 低 248 / 中 104 / 高 48 | ✅ 三档齐全 |
| **单特征最优准确率** | **0.8075**（特征 = `score_mean`） | ✅ < 0.90 → 数据**不过于干净** |
| 标签与等级口径冲突样本 | 42 条 | ✅ 存在真实边界歧义 |

### 涉及文件

`main.py`、`src/config.py`、`src/generate_data.py`、`data/scores_simulated.csv`、`data/scores_new_batch.csv`

## 第 2 天：数据预处理与手写 KNN 实现

### 当日目标

完成"缺失值处理 + 归一化 + 划分"，并用 numpy **手写 KNN**（欧氏距离 + 多数投票 + `predict_proba`）。

### 主要工作

1. `src/preprocess.py`：
   * `MedianImputer`（中位数填补，比均值稳健）与 `StandardScaler`（z-score）；
   * **关键设计：`fit` 只接收训练集**，`transform` 才用于测试集 —— 从结构上杜绝数据泄漏；
   * `random_split` 用独立 `RandomState(seed)`，保证每次划分可单独复现。
2. `src/knn_numpy.py`：
   * 欧氏距离用矩阵恒等式 `‖a−b‖² = ‖a‖² + ‖b‖² − 2abᵀ` **一次算完所有样本对**；
   * 用 `np.argpartition`（O(n) 部分排序）选 k 近邻，再对选中的 k 个排序；
   * 多数投票，**平票归为"正常"**（疑罪从无，教学场景宁可漏报不误报）；
   * `predict_proba` = k 个近邻中高风险样本的**比例**。

### 遇到的问题

**验证 B 项一开始就失败了**：我预期距离矩阵对角线上"样本到自己"的距离是 0，
但实测**不是 0**。

* 实测对角线距离最大值 **1.69e-07**，1044 条里有 **225 条非零**；
* 原因是矩阵恒等式在 `a = b` 时变成两个几乎相等的大数相减，发生**灾难性抵消**；
* 这个发现当天只当作"数值精度问题"记录，第 8 天做自匹配排除时才意识到它是个**真 bug 的根源**。

### 当日真实产出

* 预处理自检：标准化后各特征均值 ≈ 0、标准差 = 1；7:3 划分（seed=42）→ 训练 280 / 测试 120；
* KNN 手工可复算用例（查询点 `(0.9, 0.9)`，k=3）：

| 训练样本 | 标签 | 手算欧氏距离 |
|---|---|---|
| (0,0) | 0 | 1.2728 |
| (1,0) | 0 | 0.9055 |
| (0,1) | 1 | 0.9055 |
| **(1,1)** | **1** | **0.1414**（最近） |
| (2,2) | 1 | 1.5556 |

  → 近邻高风险比例 **2/3 ≈ 0.6667**，程序输出一致 ✅

### 涉及文件

`src/preprocess.py`、`src/knn_numpy.py`、`src/logreg_numpy.py`

## 第 3 天：手写 KNN 浮点复核、对照模型与留一法加速

### 当日目标

证明手写实现的**正确性**（不是"能跑就行"），并补上对照模型与高效的留一法实现。

### 主要工作

1. 新增 `src/logreg_numpy.py`：手写逻辑回归（对数损失 + L2 正则 + 自适应步长梯度下降）；
2. 新增 `src/cross_validate.py`：
   * **留一法的高效实现**：留一法训练集恒为"除自己外全部样本"，
     因此只需**一次 n×n 距离矩阵 + 对角线置 +∞**，等价于训练 n 次；
   * 写断言验证"高效实现与朴素实现**逐样本一致**"；
   * 10 次随机划分（每次用自己的训练集重新 fit 标准化器）。

### 遇到的问题

1. **浮点复核的判据一开始写错了**：我要求"向量化距离与暴力双层循环**严格相等（差异 == 0）**"，
   实测差异是 **3.55e-15** → 判定失败。
   原因：两者**运算顺序不同**（矩阵乘法 vs 逐维累加），而浮点加法不满足结合律。
   → 判据改为**相对误差 < 1e-12**，并在报告里如实写下实测差异值。
2. **计时方法不可靠**：单次计时受解释器状态影响，同一段代码两次测量可差上千倍
   → 改为**重复取样取最小值**。
3. **对照模型后端确认**：再次确认环境无 sklearn，按实训约束改用手写逻辑回归。

### 当日真实产出

| 验证项 | 结果 |
|---|---|
| 留一法加速实现 vs 朴素实现 | k=1/3/5/9 全部**逐样本一致**（不一致数 0）✅ |
| 向量化距离 vs 暴力循环 | 最大绝对差异 3.55e-15（相对 ~1e-17） |
| 逻辑回归收敛性 | 损失 0.5256 → 0.0104（线性可分小数据上准确率 1.0000） |

### 涉及文件

`src/logreg_numpy.py`、`src/cross_validate.py`、`src/evaluate.py`

## 第 4 天：k 值扫描、双口径评估与首份完整指标

### 当日目标

用数据决定 k，并把"留一法 + 10 次随机划分"双口径跑通，产出第一份完整指标与人工复算。

### 主要工作

1. `src/train_eval.py`：整合数据生成 → 预处理 → k 扫描 → 主 k 选择 → 双口径评估 → 新样本测试 → 人工复算；
2. 扫描 9 个候选 k = [1, 3, 5, 7, 9, 11, 15, 21, 31]，每个都做留一法与 10 次划分；
3. `src/evaluate.py` 增加人工复算模块（用混淆矩阵四个整数按定义手算并比对）。

### 遇到的问题

1. **k=31 看起来像是"扫到哪算哪"的最优点**，为排除嫌疑，额外扫了 41~201：

2. **新样本测试集原本只有 100 条，被 300~500 的规模约束拦住**（生成函数里写死了范围）

3. **Windows 控制台中文乱码**（默认 GBK）→ 新增 `src/utils.py` 统一把 stdout/stderr 重配置为 UTF-8。

## 第 5 天：主数据切换为 UCI 真实数据与标签泄漏排查

### 当日目标

按需求把**主数据源换成真实公开数据**，模拟数据仅作鲁棒性对照。

### 主要工作

1. `src/uci_data.py`：下载 → 清洗 → 合并 → 打标签 → 学生分组 → 难度体检；
2. 真实数据三个坑的处理：
   * 分号分隔 + 字段带引号（`"GP";"F";18;…`）→ `sep=';'` + `quotechar='"'`；
   * 混入的表头行 / 字段数不足的残行 → 关键字段缺失即剔除并记录条数；
   * **同一学生修两门课** → 用跨课程稳定的身份字段识别学生。
3. **标签泄漏排查**：计算各特征与期末成绩 G3 的相关系数。

### 遇到的问题

1. **学生分组一度形同虚设**：最初用"全部特征"匹配身份，只识别出 39 组疑似重叠；
   后来发现是把 `absences`、`G1~G3` 这些**随课程变化**的字段也当成身份信息，
   导致匹配退化成"几乎每条记录都唯一"。改用 **15 个稳定字段**后正确识别出
   **372 名同修两门课的学生**（合并后 668 名独立学生）—— 若不修，372 人的两门课记录
   会跨训练/测试集，指标偏乐观。
2. **确认标签泄漏**：`G2` 与 `G3` 相关系数 **0.905**（数学）/ **0.919**（葡语），
   `G1` 为 0.801 / 0.826。→ 决定**主口径严格剔除 G1、G2**，只用人口学 + 行为 + 家庭支持特征。
3. **三档等级退化为两档**：G3 是 0~20 的**整数**（只有 19 个取值），
   分位数的浮点切点恰好落在某个整分数上，导致"中"档被完全跳过
   （实测只剩 `{高: 637, 低: 407}`）。
   → 改为**枚举整数切点、选使三档比例最接近 0.62/0.26/0.12 的组合**，
   修正后 低 661 / 中 283 / 高 100，等级连续。

### 当日真实产出

| 检查项 | 实测值 |
|---|---|
| 数据规模 | **1044 条**（数学 395 + 葡语 649），与 UCI 官方一致 |
| 独立学生 | **668 名**，其中 **372 名**同修两门课 |
| 高风险比例（G3 < 10） | **0.2203**（数学 0.3291 / 葡语 0.1541）✅ 落在 20%~35% |
| 缺失值 | 0（清洗后） |
| 文件校验 | mat md5 `4dc304be…`、por md5 `973e7bac…` |

## 第 6 天：sklearn 主模型改造与三套评估口径

### 当日目标

按需求把**主模型换成 sklearn 实现**，手写 KNN 降为附录，并建立三套评估口径。

### 主要工作

1. `src/uci_features.py`：**固定编码 schema**（39 列），避免不同划分下维度漂移；
2. `src/model_backends.py`：模型后端抽象层（`auto / sklearn / numpy` 可切换），
   统一 `fit / predict / predict_proba / kneighbors` 签名，
   让评估代码**只写一份**、两套实现获得同口径指标；
3. `src/train_eval_v2.py`：
   * 口径 A **留一组交叉验证 LOGO**（每次留出一整名学生，668 折）；
   * 口径 B **10 次按学生分组的随机划分**；
   * 口径 C **课程外推测试**（数学↔葡语，最接近真实新样本的跨分布检验）；
   * 早期成绩消融 + 阈值调优（阈值只在训练集内部选）。

### 遇到的问题

1. **pip 通道被阻断**：受限终端下 `pip install scikit-learn` 挂起、`pip index versions` 超时 120 秒，
   而 `urllib` 可正常联网 → 在放开网络权限的终端中成功安装 **sklearn 1.7.2**；
2. **`n_jobs=-1` 直接崩溃**：joblib 起线程池需要创建命名管道，
   在被沙箱限制的环境里报 `PermissionError: [WinError 5]` → 固定 `n_jobs=1`
   （1044 条数据下多线程开销本就大于收益，指标不受影响）；
3. **消融表格式化报错**（第三个指标是字符串占位）→ 单独处理空值。

### 当日真实产出（★ 本项目最重要的结论）

**主口径 KNN(k=1)，LOGO 留一组交叉验证**

|  | 预测正常 | 预测需关注 |
|---|---|---|
| **实际正常** | TN = 688 | FP = 126 |
| **实际需关注** | FN = 151 | TP = 79 |

| 指标 | 实测值 | 与基线对比 |
|---|---|---|
| accuracy | **0.7347** | 多数类基线 **0.7797** → **低于基线 4.5 个百分点** ❌ |
| precision | 0.3854 | 判为风险的学生中只有 38.5% 真的不及格 |
| recall | 0.3435 | 只抓出 34.4% 的真实高风险学生 |
| F1 | **0.3632** | 显著偏低 |

**k 值扫描（LOGO）**：k=1 的 F1 最高（0.3632）；k 越大 recall 越低
（k=31 时 precision 0.64 但 recall 仅 **0.0696**）→ 选 k=1 的理由是
"先设 recall ≥ 0.30 门槛，再取 F1 最优"。

**对照实验（模拟 vs 真实）**：

| 数据集 | 样本 | 基线 acc | F1 | recall | **相对基线增益** |
|---|---|---|---|---|---|
| **UCI 真实（主）** | 1044 | 0.7797 | 0.3632 | 0.3435 | **−0.0450** |
| 自建模拟（对照） | 400 | 0.7025 | 0.7965 | 0.7563 | **+0.1825** |

→ **同一套评估流程、只换数据源**，模拟数据 +18.3pp、真实数据 −4.5pp。
**模拟数据上的高指标不能代表真实效果**，这是把主数据源换成真实数据的直接依据。

**早期成绩消融**：加入 G1/G2 后 F1 从 0.3632 升到 **0.5142**，
但属标签泄漏（仅用 G2 单特征阈值就可达 **0.9167** 准确率），主口径明确不可用。

### 涉及文件

`src/uci_features.py`、`src/model_backends.py`、`src/train_eval_v2.py`、`src/run_sim_compare.py`

## 第 7 天：手写 KNN 附录验证与嵌套交叉验证

### 当日目标

1. 把降级的手写 KNN 做成**有说服力的附录亮点**（证明与 sklearn 严格等价）；
2. 用嵌套交叉验证回应"k 是不是调参调出来的"这一质疑。

### 主要工作

1. `src/appendix_handwritten_knn.py`：**6 项带断言的等价性验证**；
2. `src/nested_cv_v2.py`：外层留一组（668 折）、内层独立选 k，得无偏估计；
3. 修正自匹配排除逻辑，并逐行判定"距离并列"以正确解释两套实现的差异。

### 遇到的问题（这一天挖出的问题最多）

1. **自匹配判定彻底失败**：
   * 用 `D == 0.0` 判自匹配 → **完全判不出来**（第 2 天发现的灾难性抵消：自身距离实测 1.69e-07）；
   * 改用 `D < 1e-9` 阈值 → **误删合法邻居**：真实数据里存在**特征完全相同的不同学生**
     （非对角线最小距离实测 **0.0**），而且剔除后不补足会让有效近邻数 < k
     （实测 20 条检查里 6 条出错）。
   * **最终解法**：改为**按训练集下标精确排除**，并在剔除后补取邻居保证仍返回 k 个。
2. **并列导致概率差异，判据走了两次弯路**：
   * 初版要求"所有点概率完全一致" → 误报失败（把算法语义边界当成 bug）；
   * 二版检查"第 k 与第 k+1 距离是否相等" → **漏判**：真正造成名额不足的情形是
     "第 k 名距离被多个样本共享，而第 k+1 更远"；
   * **最终判据**：逐行判定是否存在并列，要求 ① 全部点**类别预测一致**；
     ② **无并列点**的概率完全一致。

### 当日真实产出

**附录 6 项验证（UCI 与模拟两套数据 × 9 个 k 全部通过 ✅）**

| 验证项 | UCI 实测 | 模拟实测 |
|---|---|---|
| A. 向量化距离 vs 暴力双层循环 | 最大差异 **3.55e-15**，加速 935 倍 | 2.22e-15 |
| B. 距离矩阵性质 | `max\|D−Dᵀ\| = 0.0`（精确对称）；对角线最大 1.69e-07 | ✅ |
| C. 类别预测 vs sklearn | 差异 **0** | **0** |
| D. 概率 vs sklearn | 无并列却不同 **0** | 完全一致 |
| E. 留一法加速 vs 朴素实现 | 120 条差异 **0** | ✅ |
| F. 自匹配排除 | 仍含自身 0、邻居数错误 0 | ✅ |

**嵌套交叉验证**

## 八天总览

| 1 | 框架 + 模拟数据 | 硬阈值打标导致指标全 1.0000 → 改概率化打标；检出无 sklearn | 单特征最优 0.8075 证明数据不过于干净 |

### 贯穿八天的三条方法论

1. **凡是结论都要有对照线**：多数类基线（0.7797）、单特征最优（0.8017）、
   v1 模拟数据结果，三者共同支撑"真实数据上这个任务很难"这一结论；
2. **凡是优化都要验证等价性**：向量化距离、留一法加速、按索引排除自匹配 —— 每一项都写了断言；
3. **凡是失败都要写进报告**：模型低于基线、概率退化为 0/1、k=1 无法分档、
   数据被污染 —— 这些都如实记录，而不是只展示好看的数字。
